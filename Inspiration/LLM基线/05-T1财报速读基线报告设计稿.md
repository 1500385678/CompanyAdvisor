## 4. 方法与流程

### 4.1 端到端跑批脚本(待写)

- **入口**:`scripts/llm_eval_runner.py`(本稿不入库,09-04 跑批前单独提交)
- **职责**:① 加载 25 份年报 PDF → ② 调 `pdfplumber_demo.py --extract` 抽 pages JSON → ③ 调 T1 prompt → ④ 调 LLM provider(Claude Sonnet 4 / GPT-4o / Qwen-Finance / 本地 Ollama,4 模型对比)→ ⑤ 输出 25 × 4 = 100 条结果到 `samples/llm_eval/05-t1-results.jsonl`
- **复跑**:同输入下 4 模型各跑 1 次,温度 0,seed 固定 42

### 4.2 4 档评分(沿用 01 设计稿 §4)

| 档位 | 含义 | 触发 |
|------|------|------|
| 4 精确 | 数字 100% 命中表,evidence 原文 ≤ 60 字,语义无歧义 | 人工 + LLM 自评 `confidence=high` |
| 3 可接受 | 数字 100% 命中,evidence 原文 > 60 字或语义略模糊 | 人工认 3 档 + 自评 `medium` |
| 2 可改 | 数字错 / 漏,evidence 引用错位,但**4 段结构对** | 人工认 2 档 + 自评 `medium/low` |
| 1 不可用 | 结构错 / 字段缺失 / 编造数字 | 人工认 1 档 + 自评 `low` |

### 4.3 盲评规则(防止自评偏差)

- **5 公司 × 1 主模型** = 5 票飞书 P0 用户盲评(张勇 1 票 + 至少 4 位种子用户匿名)
- **盲评材料**:仅给 LLM 输出 + 真实年报原文(无 prompt / 无模型名 / 无自评档)
- **评分维度**:**信息准确度** + **evidence 原文度** + **结构完整性** + **可读性**(4 维 4 档,沿用 01 设计稿 §4 校准表)
- **差异处理**:盲评 < 自评 1 档以上 → 计入"自评偏差"统计,触发 prompt 复核

## 11. 不做什么

- **不实际跑 LLM**:本稿为骨架,无 LLM provider 接入(等张勇分配 token + 选 provider)
- **不绑死 1 个模型**:4 模型对比是基线报告的核心价值,4 模型并列
- **不改 T1 prompt v0.1**:基线报告校准 v0.1,prompt 优化点入 v0.2(09-06 跑批后)
- **不扩 5 公司之外**:Phase 0 截止 09-06 仅 3 天,5 公司 + 4 模型是临界最小集合
- **不绑死盲评用户**:飞书 P0 用户列表由张勇拉(本稿仅提要求,不定名单)
- **不勾选 [项目开发计划.md](../../项目开发计划.md) §5 #4 checkbox**:**本稿是骨架,不闭合基线报告落地项**;基线报告 09-06 跑批完成时一并勾选
- **不写 4 任务外的新任务**(如 T5 估值/T6 行业):本稿仅 1-4 任务闭环,5+ 留 Phase 1

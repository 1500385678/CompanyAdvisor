> **入库日期**:2026-08-29
> **对应主计划**:[项目开发计划.md §5 Phase 0 第 4 项](../../项目开发计划.md)

> **维护**:22-公司-Company 行业顾问

## 1. 背景与目标

- **来源**:项目开发计划 §3 核心功能 + §6 Phase 1 MVP 的 4 个模块 — **财报速读** / **护城河评估** / **对标矩阵** / **事件时间线**。这 4 个模块在 Phase 1 都要走 LLM 做"理解 + 结构化",但**没有任何基线**——选什么模型、prompt 怎么写、输出怎么校准都没标准。
- **目标**:在 Phase 0 结束前(09-06)建立 **4 类任务 × {输入契约 / Prompt 模板 / 输出契约 / 评分标准}** 的最小可复用基线,供 Phase 1 直接接 5-10 家头部公司真实数据跑通。
- **现状**(2026-09-02):4 项中 **4/4**(T1+T2+T3+T4)全部落地 → **§5 Phase 0 #4 整段可勾选闭合**。T1 (08-29) → T2 (08-31,顺延自 08-30 cron 断档) → T3 (09-01,顺延自 08-31 占用 T2 排期) → T4 (09-02)。

## 2. 4 类任务一览

|---|---|---|---|---|---|

>
> **3.5 T4 索引**:T4 事件归因完整契约见 [04-T4事件归因prompt-v0.1.md §3-§7](./04-T4事件归因prompt-v0.1.md)(输入 JSON + 8 类事件类型 + Prompt A 规则过滤 + Prompt B 抽取+因果链 + Pydantic schema + 4 档校准 + 验证步骤)。**字段对齐**:Evidence 模型直接复用护城河 schema §6(同字段名 + 新增 `doc_id` 回链到 event_corpus);`impact_dimensions` 严格用护城河 5 维 D1-D5,便于 Phase 1 把 T4 输出叠加到 T2 护城河评估上。

## 3. T1 财报速读 Prompt v0.1

### 3.1 输入契约(基于 [pdfplumber_demo.py](../../scripts/pdfplumber_demo.py))

```jsonc
{
  "source": "samples/_sample-fy2025.pdf",
  "page_count": 2,
  "pages": [
    {
      "page_no": 1,
      "text": "...",          // 段落级纯文本,可能含中文
      "tables": [
        {"table_no": 1, "rows": [["科目", "金额(亿元)"], ...]}
      ]
    }
  ]
}
```

**真实场景约束**(Phase 1 必踩,先记):

- 中文年报需切换到 CID 字体(STSong-Light)才能正确抽取,否则 `extract_text()` 返回乱码
- 三大表常跨多页(资产负债 2-3 页),表格分页需合并
- 章节标题(MD&A / 经营回顾 / 风险)用纯文本 anchor 识别,Phase 1 写轻量规则

### 3.2 Prompt 模板(直接给 Claude / GPT-4o 用)

```
你是资深卖方分析师助手。给定一份年报/季报的 pdfplumber 抽取结果(每页 text + tables),请输出**结构化四段摘要**。

## 输入
- 公司名称: <company_name>
- 报告期: <period, 如 "FY2025" 或 "1H2026">
- 抽取数据: <json_payload 摘要,截断到前 N 页 + 关键表>

## 输出(JSON,严格遵循 schema,不要多余字段)
{
  "company": "<公司名>",
  "period": "<报告期>",
  "performance": {
    "headline": "<1 句话业绩总览,如 营收同比 +9.8% 净利 +14.2%>",
    "yoy_revenue": "<百分比,保留 1 位小数,可空字符串>",
    "yoy_net_income": "<百分比,同上>",
    "qoq_revenue": "<季度报告才填,否则空字符串>"
  },
  "drivers": [
    {"factor": "<驱动因素,1 句话>", "evidence": "<引用原文,≤ 60 字>"},
    ...   // 1-3 条
  ],
  "risks": [
    {"risk": "<风险点,1 句话>", "evidence": "<引用原文,≤ 60 字>"},
    ...   // 1-3 条
  ],
  "guidance": {
    "next_period": "<下一报告期展望,如 全年指引上调 5-8%>",
    "key_watch": "<投资者关注点,1 句话,空字符串表示无明确指引>"
  },
  "confidence": "high | medium | low"   // LLM 自评,基于输入质量
}

## 约束
- 严格基于输入数据,不要外部知识
- evidence 必须从输入 text/tables 复制,不允许编造
- 数字一律从 tables.rows 提取,不要心算
- 中文输出,标点用全角
```

### 3.3 输出契约(JSON Schema,Pydantic 雏形)

```python
from pydantic import BaseModel, Field
from typing import Literal

class DriverItem(BaseModel):
    factor: str = Field(..., min_length=4, max_length=80)
    evidence: str = Field(..., min_length=5, max_length=80)

class RiskItem(BaseModel):
    risk: str = Field(..., min_length=4, max_length=80)
    evidence: str = Field(..., min_length=5, max_length=80)

class FinancialSummary(BaseModel):
    company: str
    period: str
    performance: dict          # 必含 headline / yoy_revenue / yoy_net_income / qoq_revenue
    drivers: list[DriverItem] = Field(..., min_length=1, max_length=3)
    risks:   list[RiskItem]   = Field(..., min_length=1, max_length=3)
    guidance: dict             # 必含 next_period / key_watch
    confidence: Literal["high", "medium", "low"]
    version: str = "financial_summary-v0.1"
```

### 3.4 4 档评分标准(校准用)

| 档位 | 含义 | 通过条件 |
|---|---|---|
| 4 = **完全可用** | 业绩数字 + 驱动/风险原文引用 + 指引均准确,无 hallucination | 关键数字与原文表格一致;evidence 可定位;指引若有明示则对、无明示则空 |
| 3 = **基本可用** | 业绩数字准,驱动/风险表述合理但 evidence 略泛化 | 数字一致;evidence 存在但允许轻微意译;指引可空 |
| 2 = **可参考** | 业绩数字 1 处偏差 / 驱动或风险漏 1 项 / evidence 编造 | 关键数字允许 1 处四舍五入差异;evidence 必须存在但允许合理推断 |
| 1 = **不可用** | 数字错 / 严重 hallucination / JSON schema 破 | 数字与原文不符;evidence 找不到原文;字段缺失或乱码 |

**Phase 0 收口标准**:至少 1 个模型在 5 份样例年报(种子清单前 5 家)上**平均 ≥ 3 档**。

### 3.5 验证步骤(本地最小闭环)

1. `python scripts/pdfplumber_demo.py --extract <real_pdf>` 拿到 JSON 输入
2. 把 JSON 截断到前 10 页 + 关键表(防 token 爆)
3. 用 LLM CLI / API 跑 §3.2 prompt,得 §3.3 JSON
4. 用 §3.4 4 档标尺人工盲评 5 份
5. 写报告:`Inspiration/LLM基线/02-财报速读基线报告.md`(Phase 0 收口时落地)

## 5. 不做(本期边界)

- **不做模型对比基准**(本设计稿只定义契约,不跑多模型;Phase 1 MVP 选型时再做 Claude vs Qwen-Finance vs GPT-4o 对比)
- **不做线上评测管线**(Phase 0 只人工盲评 5 份,Phase 1 再做 LLM-as-judge 自动评测)
- **不接 RAG**(4 类任务 Phase 0 都不接外部知识库,纯 LLM + 输入契约;Phase 1 财报速读接 Milvus 公告检索)
- **不做多语言**(本设计稿只服务中文年报,英文 10-K 在 Phase 2 单独建契约)

## 4. 方法与流程

### 4.1 两段式流程(规则预处理 + LLM 抽取/归因)

**第一段:规则引擎预处理**(沿用 04 prompt §4.1 过滤表)

```python
# 沿用 04 prompt §4.1 规则引擎契约(Phase 0 手工对照,Phase 1 写 scripts/event_corpus_preprocess.py)
def event_corpus_preprocess(raw_corpus, target, options):
    """输入 5 年公告/新闻/研报 + target,输出 30-100 条精修素材"""
    corpus = []
    for doc in raw_corpus:
        # 去重:同标题 + 同 publish_date 合并为 1 条,保留信息密度最高版本
        if is_duplicate(doc, corpus):
            continue
        # 时间窗:仅保留 ≤ date_window_years(默认 5 年)
        if not within_window(doc["publish_date"], options["date_window_years"]):
            continue
        # 截断:每条 text 截断到 500 字,优先保留"事件核心"段
        doc["text"] = truncate(doc["text"], max_chars=500, keep="middle")
        # 来源优先级:公告 > 研报 > 权威媒体 > 自媒体(用于多源去重时优先保留)
        # 噪音过滤:关键词黑名单(招股书模板段/封面页/目录/致谢)
        if is_noise(doc["text"]):
            continue
        # 事件候选预筛:关键词命中"收购/回购/分红/减持/中标/许可/诉讼/新品/任命/业绩预告/亏损/重组/分拆/上市"等 ≥ 1 个
        hit_types = event_keyword_hit(doc["text"])
        doc["rule_pre_kept"] = True
        doc["rule_event_type_hint"] = hit_types  # 软提示,LLM 可改
        corpus.append(doc)
    return corpus
```

**第二段:LLM 抽取 + 归因 + 因果链推理**(沿用 04 prompt §4.3 Prompt B 模板)

```
输入:target JSON + event_corpus(30-100 条,带 rule_event_type_hint)+ moat_hint(可选,来自 06 报告)+ options
输出:events(8-20)+ causal_chains(1-3)+ major_themes(1-3)+ limitations(1-3)
约束:LLM 只能从 event_corpus 抽取,不允许编造未在素材中出现的事件(04 §4.3 显式约束 + 池外事件 0 容忍)
```

| 3 基本可用 | 抽取基本全 + 类型大致准 + 因果合理但 evidence 略泛化 | events ≥ 8;允许 1-2 处类型误判(可上调/下调);causal_chains rationale 合理;limitations 存在 |
| 2 可参考 | 事件漏 2-3 个明显该抽的 / 因果链 evidence 引用错误 / 影响维度有编造 | events < 8 或 > 20;causal_chains 含不在 events 中的 id;magnitude 与实际影响明显不符 |
| 1 不可用 | 大量编造事件 / 因果链完全虚构 / evidence 找不到原文 / JSON schema 破 | events 含素材池外事件(致命);causal_chains 全凭想象;字段缺失或乱码;events < 5 或 > 25 |

### 4.3 端到端跑批脚本(沿用 05.1 骨架,扩展 T4 适配)

- **入口**:`scripts/llm_eval_runner.py --task t4`(05.1 骨架已就位,需在 MODELS + 任务清单中加 `t4` 分支)
- **职责**:① 加载 5 公司 × 5 年公告/新闻/研报 = 5 份 event_corpus(每份 30-100 条) → ② 调 T4 prompt A 规则预处理(无 LLM) → ③ 调 T4 prompt B(LLM 抽取/归因) → ④ 输出 5 × 4 = 20 份结果到 `samples/llm_eval/08-t4-results.jsonl`
- **复跑**:同输入下 4 模型各跑 1 次,温度 0,seed 固定 42

### 4.4 盲评规则(防止自评偏差 + 因果链主观性偏差 + 池外事件漏判)

- **5 公司 × 1 主模型** = 5 票飞书 P0 用户盲评(张勇 1 票 + 至少 4 位种子用户匿名)
- **盲评材料**:给 LLM 输出 + 真实 event_corpus(无 prompt / 无模型名 / 无规则预处理标记 / 无自评档 / 无 moat_hint)
- **评分维度**:**抽取完整度 + 类型准确度 + 因果链合理性 + 影响维度准确度(4 维 4 档)**
- **事件抽取"金标"**(盲评锚点):飞书 P0 用户对 event_corpus 独立抽 8-20 个有效事件 + 类型,金标 = 多数票(≥ 3/5 同意该事件存在 + 类型一致)
- **因果链"金标"**(盲评锚点):飞书 P0 用户对"金标事件集"独立判 1-3 条因果链,金标 = 多数票(≥ 3/5 同意该链合理)
- **差异处理**:盲评 < 自评 1 档以上 → 计入"自评偏差"统计;池外事件盲评与 LLM 不一致(LLM 报有,实际无)→ 计入"池外事件 0 容忍"违反,触发 prompt 复核
- **moat_hint 复用验证**:英伟达(无 moat_hint)vs 4 公司(有 moat_hint)4 维命中率差异 → 验证 moat_hint 是否真的提升抽取完整度 / 影响维度准确度

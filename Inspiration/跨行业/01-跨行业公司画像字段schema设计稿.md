## §3 行业扩展位(每个行业 1 个 JSON 段)

> 通用字段是"必填"位;行业扩展位是"选填"位,各行业顾问可挂自己的字段。
> **22-公司**:自身没有扩展位(因为本 schema 就是 22-公司的视角;若 22-公司想看消费/医药/...行业的扩展位,需读对方 schema)
> **17-生物**:可挂 `pipeline_drugs`(在研管线) / `clinical_phase`(临床阶段) / `fda_approval`(FDA 批准)
> **20-经济**:可挂 `gdp_contribution`(GDP 贡献) / `policy_sensitivity`(政策敏感度) / `employment_scale`(就业规模)
> **23-盈利**:可挂 `unit_economics`(单位经济) / `ltv_cac_ratio`(LTV/CAC) / `burn_rate`(烧钱率)

**接口契约**:

```json
{
  "common": { /* §2 通用 23 字段 */ },
  "industry_extensions": {
    "biotech_17": { "pipeline_drugs": [...], "clinical_phase": "...", "fda_approval": [...] },
    "macro_20":   { "gdp_contribution": "...", "policy_sensitivity": "high", ... },
    "profit_23":  { "unit_economics": {...}, "ltv_cac_ratio": 3.2, "burn_rate": ... }
  }
}
```

**关键设计**:

- 通用字段是"公司画像必填",行业扩展是"该行业才填";同一公司如果 3 行业都相关(如腾讯),3 边都挂扩展
- 扩展位字段命名遵循 `[业务指标]_[单位/口径]` 习惯(如 `clinical_phase` = 一期/二期/三期/NDA)
- 任何 1 行业顾问新增扩展字段,**不需要**其他 2 边同意(本字段属于该行业;但写入前需在 17/20/23 群内"通报"避免重名)

## §5 跨字段一致性约束(对齐时必须遵守)

| # | 约束 | 违反后果 |
|---|---|---|
| C1 | `revenue_5y` 单位统一"亿元"(非"万元"/"美元") | 跨公司对标时单位错乱 |
| C2 | `ticker` 6 位股票代码必须带后缀(600519.SH / 0700.HK / AAPL.US) | 跨市场可比性失败 |
| C3 | `gross_margin_5y` 口径 = (营业收入 - 营业成本) / 营业收入 | 跨公司毛利比较错位 |
| C4 | `roe_5y` 口径 = 归母净利润 / 平均归母权益(分母用平均) | 跨年 ROE 不可比 |
| C5 | `moat_score` 必须沿用 22-公司护城河 schema v0.1 D1-D5 5 维加权 | 护城河评估不能跨公司比较 |
| C6 | `key_events_5y` 分类必须沿用 T4 事件归因 8 类(融资/并购/管理层/诉讼/产品发布/监管/分红/其他) | 跨公司事件检索失败 |
| C7 | `business_segments` 行业 8 大类(消费/医药/互联网/新能源/半导体/金融/汽车/制造)直接借用 22-公司 8 分类 | 跨行业对标聚类失效 |
